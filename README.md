# ad-group

Сайт строительной компании AD Group: главная, проекты и страницы ЖК (Vatan Residence, Urgut Tower), «Направления», «Вакансии», форма заявки в модальном окне, админка.

**Стек:** Next.js (App Router, Cache Components) · TypeScript · Tailwind CSS v4 · shadcn/ui · react-icons.

## Запуск

```bash
npm install
cp .env.example .env.local   # задайте ADMIN_PASSWORD и SESSION_SECRET
npm run dev                  # http://localhost:3000
npm run build && npm start   # production
npm run lint
```

## Админка

`/admin` (вход по паролю `ADMIN_PASSWORD`). Что можно делать:

- **ЖК и проекты:** названия и описания на RU/UZ/EN, тип, статус, год, цена, обложка, галерея (порядок и удаление фото), цифры и преимущества; галочка «Показывать большим блоком на главной»
- **Новости:** заголовок, текст, дата, картинка
- **Вакансии:** название, отдел, город, занятость, описание, требования, скрыть/показать; отклик с сайта попадает в «Заявки» с названием вакансии
- **Настройки:** руководитель (фото, имя, должность, цитата, текст) и контакты (телефон, e-mail, адрес, соцсети); блок руководителя на главной и странице вакансий, подвал берут данные отсюда
- **Заявки:** всё, что отправлено формами на сайте

Изменения появляются на сайте сразу. Фото при загрузке сжимаются и переводятся в WebP (до 12 МБ на файл, JPG/PNG/WebP/AVIF).

### Где хранятся данные

**Neon (Postgres), рекомендуется.** Задайте `DATABASE_URL` (строка подключения Neon, лучше «pooled», с `-pooler` в адресе). Таблицы создаются и заполняются стартовыми данными из `src/lib/seed.ts` сами при первом обращении. Проекты, новости, вакансии и настройки лежат в таблицах как jsonb, заявки в таблице `leads`, загруженные фото в таблице `uploads` (WebP, обычно 100–400 КБ) и отдаются через `/uploads/[name]`. Так сайт и админка работают на Vercel и любом serverless-хостинге без отдельного файлового хранилища.

**Локально без базы.** Если `DATABASE_URL` пустой, данные лежат в `data/` (или в `DATA_DIR`): `content.json`, `leads.json`, `uploads/`. Папка не попадает в git. Файл создаётся из стартовых данных при первом запуске; если на диске лежит файл старой версии, он сохраняется как `content.v<версия>.<время>.bak.json`.

Весь доступ к данным собран в `src/lib/server/store.ts` (выбирает хранилище), реализации: `pg-store.ts` и `file-store.ts`. Проверка Postgres-хранилища на встроенной базе без внешних сервисов: `npm run test:store`.

Фото сжимаются в браузере перед отправкой (у Vercel лимит тела запроса около 4,5 МБ), а на сервере проверяются, очищаются от метаданных и переводятся в WebP.

### Безопасность

- Сессия — подписанная HMAC cookie (httpOnly, sameSite=lax, secure в production) на 7 дней
- `src/proxy.ts` быстро отправляет на вход запросы без cookie; подпись проверяется в layout админки и в каждом server action
- Загрузки: проверка типа и размера, перекодирование через sharp (метаданные удаляются), случайные имена, раздача через `/uploads/[name]`; имя файла проверяется до обращения к хранилищу
- Форма заявки: проверка на сервере и скрытое поле-ловушка для ботов

## Структура
- `src/app` — страницы: `/`, `/directions`, `/vacancies`, `/projects/[id]`, `/admin/*`, `/uploads/[name]`
- `src/components/site` — секции сайта; `src/components/admin` — формы админки; `src/components/ui` — shadcn
- `src/actions` — server actions (заявки, админка)
- `src/lib/types.ts`, `seed.ts`, `content.ts` (тексты интерфейса RU/UZ/EN), `content-source.ts` (чтение с кэшем), `server/` (хранилище, авторизация)
- `public/assets`, `public/textures`, `public/vatan`, `public/team` — логотипы, мраморная текстура, фото ЖК, фото основателя

## Демо-ограничения
Данные Vatan Residence взяты из официального каталога, текст Urgut Tower составлен по его визуализациям; цифры на первом экране, история, новости, вакансии, адрес и e-mail — заглушки (меняются в админке или в `src/lib/content.ts`). Имя основателя — «Имя Фамилия». Шрифты: Manrope (текст, полная кириллица) и Playfair Display (заголовки); фирменные Cairo Now Extended и Delmon Delicate недоступны, заменены.
